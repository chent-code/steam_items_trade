# 自动化倒余额策略 · 可行性调研

> 调研日期:2026-10-22
> 问题:能否用脚本每 10 分钟扫挂刀比例、发现捡漏价自动买入,AI 复核,择机卖出?
> 本文回答两件事:① 跑得通吗;② 需要哪些资源。

---

## 一、结论

**跑得通,但不是"一条命令"的事。** 技术可行性有成熟的开源证据(Steamauto、Buff-Bot 等项目已实现 BUFF/悠悠有品的自动登录、下单、收发货多年),真正的瓶颈不在代码,在四件事:**平台风控、凭据安全、竞争节奏、以及"AI 复核"在实时链路里的正确位置**。

分平台看:

| 平台 | 自动化成熟度 | 凭据 | 主要障碍 |
|---|---|---|---|
| 网易 BUFF | **高**(开源项目完整覆盖:登录态维持、下单、收发货、自动上架) | Session cookie | 风控(滑块/异地登录)、下单 API 带风控字段、1.5% 手续费 |
| 悠悠有品 | **中,且在恶化** | App token(get_uu_token.py 获取) | 2025 年起主动反自动化:客户端指纹校验(AppVersion/DeviceId/uk)、"85100 版本过低"风控话术、token 随时可能失效需重取 |
| Steam(收货/卖出) | 成熟 | 令牌参数(shared_secret 等) | 7 天交易保护期(这是策略结构,不是障碍) |

实测佐证(本次调研匿名探测):
- `POST buff.163.com/api/market/goods/buy` → 存活,返回"请先登录"(接口形态与社区一致)
- UUYP 匿名行情接口 → 405/85100 风控拦截;第三方项目实测 6 个客户端版本号全部被拒

**一个必须先对齐的认知:10 分钟捡漏版 ≠ 已回测的周度版。** 回测验证的是"按日频 ask 买入、持有 7 天、挂单退出"。10 分钟捡漏是它的更激进变体——买入的是瞬态低价 ask。这个变体多了一个回测没建模的未知数:**抢购成功率**。现役 sniper 机器人是秒级轮询,你 10 分钟一扫,最深的漏大概率已经被吃掉。这不是否决理由,而是说 L0 阶段(见路线)要先量这个数。

## 二、推荐架构(三档自动化)

```
┌─────────────────── 你本机常驻 watcher ───────────────────┐
│ 1. 数据:csqaq exchange_detail,每 10 分钟(1 req/s 合规)      │
│ 2. 规则引擎(确定性,代码写死):                              │
│    比值阈值 / Steam求购挂单量下限 / 日成交量下限             │
│    / 单品限购 1 件 / 当日预算上限 / 黑名单 / 去重            │
│ 3. 执行:平台下单 API(session cookie / token)               │
│ 4. 护栏:cookie 失效检测、连续亏损熔断、全额通知              │
│ 5. 卖出:7 天保护期结束 → 自动以当前 ask 挂单(时机基本可自动化)│
│ 6. 通知:Apprise(WxPusher/Server酱/钉钉/邮箱 任选)          │
└──────────────────────────────────────────────────────┘
```

**关于"AI 复核"——先泼一盆现实的冷水,再给可行的位置。**

10 分钟节奏下,"每单都让 AI 实时审批"不可行:我不可能常驻在线等下一单,而且这个频率下审批本身没有信息增益(信号就是那个比值,规则引擎判得和 AI 一样快)。AI 复核的正确位置是**异步**的:

1. **事前**:规则引擎的每条阈值由我基于回测证据给出、你确认——审批逻辑固化在代码里,而不是每次问 AI。
2. **事中留痕**:每笔买入(含触发它的完整证据链:比值、Steam 求购挂单量、过去 7 天 Steam/平台涨幅、尖峰分位、当时价差)写入日志。
3. **事后**:我定期(每日/每周,可用 WorkBuddy 定时任务,最细小时级)复盘放行记录 vs 未放行记录,标注"这单我不该放/该放没放",迭代阈值。这才是 AI 复核产生价值的形态。

另一处边界要诚实说明:**WorkBuddy 的定时任务最细是小时级,做不了 10 分钟级**;10 分钟监听必须是你本机的常驻脚本。我的定位是:写脚本、异步复盘、异常处置建议——不是 7×24 值班员。

## 三、资源清单(按档位)

### L0 —— 检测+通知,你手动下单(现在就能跑,零新增平台风险)
- 检测只走 csqaq(已有 token),不碰平台,无封号增量风险
- 产出:命中推送 + 我的异步复核意见
- **这一阶段真正要量的数:你收到通知后手动下单,抢购成功率是多少、成交价与通知价差多少**——这是决定 L1 值不值的核心参数
- 需要你提供:一个通知渠道(WxPusher/Server酱/钉钉/邮箱 任选)

### L1 —— BUFF 单平台自动买入(建议首个自动化档)
- BUFF 专用**小号**(实名+绑 Steam+手机令牌),Session cookie
- 钱包余额自充:建议起步 1000–2000 元(单笔 50–200 × 日限 5 笔),明确这是可全损的风险资金
- 我写 watcher + 下单模块(参考 Steamauto/Buff-Bot 的登录态维护)
- 需要你提供:cookie、通知渠道、确认接受"该账号可能被封"的风险

### L2 —— 双平台全自动(不推荐初期)
- 加 UUYP token + Steam 令牌参数(shared_secret/identity_secret,自动收发货需要)
- 接受 UUYP 反自动化升级导致的频繁失效与维护成本

**资金安全原则(无论哪档)**:下单走平台钱包余额扣款,**不需要给任何脚本支付密码或银行卡**;session cookie/token 等于账户控制权,必须用专用小号、只放最小余额、不装来路不明的依赖库。

## 四、风险清单(按严重度)

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| 1 | **平台封号/风控** | 自动化违反两平台用户协议(UUYP 协议明确禁止突破反爬);BUFF 有滑块/异地风控;UUYP 2025 起主动升级对抗 | 专用小号、低频拟人间隔、可接受损失=该号余额;封号视为该档位的沉没成本 |
| 2 | **抢购竞争** | 秒级 sniper 机器人先于你;回测的"按 ask 买入"是乐观假设 | L0 阶段实测成功率;10 分钟档可主动避开竞争最激烈的价格带,只做"中深度折价+高流动性" |
| 3 | **Steam 商业红锁** | 高频交易同一饰品+不游玩 → 交易限制 | 分散品种(回测 top-20 本身就是分散的)、控制单品种频率 |
| 4 | **策略前向失效** | 回测≠前向:容量、成交率、卷速度都未知 | L0→L1→L2 渐进;每步用真实成交数据校准 |
| 5 | 资金安全 | cookie 泄露=余额被盗 | 专用小号、最小余额、依赖库审计 |
| 6 | 合规 | 2026 饰品补税话题(增值税/个税) | 留存盈利记录,大额前咨询 |
| 7 | 操作风险 | 脚本 bug 买入错误品种/数量 | 单品限购、日预算、熔断、全量通知 |

## 五、建议路线

- **第 0 周(L0)**:watcher 上线(检测+通知+异步复核)。零平台风险。量三个数:信号命中率、你的抢购成功率、通知→成交的滑点。

## 七、UUYP 深挖(v2,2026-10-22 补充)——结论上修

针对"UUYP 手续费明确优于 BUFF,再调研一下 UUYP 交易有没有可行方案":

### 7.1 交易全闭环已有开源实现

Steamauto 内置的 `uuyoupinapi` 库(逐方法核对源码)覆盖了几乎整个交易闭环:

| 环节 | 接口 | 说明 |
|---|---|---|
| 登录/凭据 | `SendSignInSmsCode` + `SmsSignIn` | **短信验证码登录,自动拿 token,不需要抓包**;token 失效码 84101 |
| **求购(被动买入)** | `publish_purchase_order` / `updatePurchaseOrder` | 创建/改价求购单,参数含 purchasePrice/Num、needPaymentAmount(下单即冻结余额) |
| 库存 | `GetUserInventoryDataListV3` | 可强制刷新 |
| **卖出** | `SellInventoryWithLeaseV2`(上架)、`PriceChangeWithLeaseV2`(改价)、`OffShelf`(下架) | 卖出端全自动化 |
| 交付 | `get_wait_deliver_list` + `send_offer` | 自动发 Steam 报价(报价号有三种获取途径,库已处理) |
| 行情 | `get_least_market_price` 等 | 风控码 84104("悠悠风控,暂时无法获取价格") |
| 认证 | authorization(Bearer token)+ uk(加密接口获取,30s 缓存)+ 设备指纹 + okhttp UA + App-Version | 指纹猫鼠游戏是主要维护成本 |

未实现:钱包充值/提现接口 → **充值手动做**(支付宝入金),不影响自动化。

### 7.2 费用口径修正(重要)

官方帮助页(现行 App v5.48.2):**"平台将对所有普通出售、还价、求购订单向卖家收取 1% 的交易手续费"**(出售大会员可折扣/全免;私密出售不收)。提现 1%(单笔最低 2 元、日限 3 次)。**买方手续费 0%**。

- 修正:我此前引述的"UUYP 0 交易手续费"来自媒体口径,现行官方是**卖家 1%**(求购成交也算卖方方向收费)。你的策略是"买入(0 费)→ 卖出(1%)"→ 回合成本 **≈1% + 提现 1%**,对比 BUFF 的 1.5% + 1%:**UUYP 仍省 ~0.5pp/回合,但不是 1.5pp**。以 App 内实时页面为准。
- 求购单成交时你是买方,0 费;冻结的资金在撤单后释放。

### 7.3 架构上修:UUYP 求购单版可能优于"10 分钟抢单"版

`publish_purchase_order` 的存在,让 UUYP 路线可以**绕开抢单竞争**——不做 10 分钟扫价狙击,而是**挂被动求购单**:

```
信号(csqaq,10分钟):折扣比 + Steam领先幅度 + 流动性过滤
  ↓ 命中
执行:在目标价挂求购单(目标价 = Steam求购价 × 0.8696 × 目标折扣)
  ↓ 被动等成交(卖方主动砸给你)
风控:Steam 求购价跌破阈值 → 自动 updatePurchaseOrder 改价/撤单
卖出:7天保护期结束 → 自动上架(ask)→ 成交
```

对比 10 分钟狙击版的优劣:
- **不再拼手速**:求购单是 standing order,卖方砸给你,天然解决"抢购成功率"这个最大未知数
- **与你策略的机制一致**:回测证明收益来自"平台向 Steam 收敛 + 退出流动性",求购单本质是**在收敛路径上提供流动性**——你挂的买价就是别人恐慌出货的接盘位
- **代价:逆向选择**。求购单成交的时刻,往往是价格正在砸穿你的价位的时候(没人会在涨的时候卖给你)。缓解:Steam bid 触发式改价/撤单、仓位控制;这点必须在 L0/L1 实测成交质量
- 代价:资金占用(求购单冻结余额)、成交节奏慢于狙击

### 7.4 成本模型修正(v3,2026-10-22)——提现费移出回合成本

用户修正(采纳):提现不是每回合发生的——长期复投、攒够收益后再决定余额处置。修正后:

| 环节 | UUYP | BUFF |
|---|---|---|
| 求购买入(买方) | **0%** | **0%** |
| 卖出退出(卖方,含供应求购) | **1%** | **1.5%** |
| 提现 | 1%(一次性终值;口径存疑,另有 0.1% 说法;可经载体 P2P 绕行) | 1%(同) |
| **每回合净成本** | **≈1%** | **≈1.5%** |

- 回测数字影响:回测已按每期 1% 扣费——换成"UUYP 卖出费"标签后数学相同,**报告数字无需修改**(超额 +3.53%/周 对双边同费率近似不变;绝对净收益 ask 退出 ≈ +2.0%/周)。BUFF 口径再 ×0.985/0.99。
- 余额出口多元化:余额(买方 0 费)→ 买高流动性载体(宝瓶)→ 闲鱼/论坛 P2P 变现,绕开提现费。核算要点:载体闲鱼折价 vs 1% 提现费;闲鱼虚拟商品担保 3 天/部分订单 0.6% 服务费/P2P 纠纷风险;提现费率两说(1% vs 0.1%)以 App 实时为准;P2P 不改变纳税义务。
- 推论:长期复投模式下"退出"是终值决策——每回合不可免成本仅卖出手续费,这是该生态摩擦低的结构性原因。

### 7.5 交易机制参考(2026-10-22 补充)——平台是非托管撮合市场

完整时序:①上架=库存同步+记录 assetid/价格(**物品不离开 Steam 库存**)→②成交=买家付款进平台托管账户→③发货=Steam 交易报价,物品**点对点**从卖家库存到买家库存,平台物理不经手→④买家接受报价,物品进入 7 天交易保护期→保护期结束平台结算托管资金到卖家余额。

发货两模式:**A 卖方自己发**(手动/Steamauto 用自己的 Steam 凭据);**B 平台代理**(绑定 Steam 时走 OAuth,平台持有会话,成交后代发报价——Steamauto 文档"发起报价时将加密 Steam Cookie 提交给 BUFF"、uuyoupinapi 的 send_offer(orderNo) 即此模式)。

自动化推论:①卖出自动化=上架/改价走平台 API + 发货走模式 B(零代码,已随绑定授权)或模式 A(需 Steam 凭据,Steamauto 式);②资金周转实际=买入冻结7天+卖出结算7天,长于名义周度;③"已发货订单"须标记不可逆,防脚本重复处理;④撤销交易=卖方发货后反悔会被禁市30天,平台延长结算即防此。

### 7.6 UUYP 路线的资源与风险(修订)

资源:
- UUYP 账号(实名+绑 Steam+令牌);token 走短信登录自动获取,无需抓包
- 钱包余额(支付宝充值,求购单冻结用)
- 现有 csqaq token;watcher 本机常驻

风险(修订排序):
1. **指纹猫鼠**:`App-Version`/uk/设备指纹任一被平台升级拒识 → 84104/84101/85100,需跟随 Steamauto 社区更新(历史上是"修一次用数月"的节奏)
2. **求购逆向选择**:成交时点偏向价格下跌;用 Steam-bid 触发的改价/撤单缓解
3. Steam 商业红锁、资金安全(专用小号)、合规:同主报告
4. 求购费率/有效期/挂单数量上限:**需在 App 内实测确认**(免费档求购单数量上限未知)
